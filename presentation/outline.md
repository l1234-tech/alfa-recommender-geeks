# Презентация — скелет (8–12 слайдов)

Принципы Changellenge: один слайд = одна мысль, **вывод в заголовке** (не тема),
утверждения подкреплять фактами/метриками/сравнением с бейзлайном, показывать
продукт (скриншоты), а не только рассказывать. Эксперт смотрит PDF без нас —
всё должно быть понятно без устных пояснений.

---

### Слайд 1 — Титул + как проверять
- Название решения, трек, команда (5 ролей).
- **Порядок проверки:** `docker compose up --build` → http://localhost:8000/docs.
- Ссылка на репозиторий; ссылка на развёрнутый интерфейс (если будет).
- _Заголовок-вывод: напр. «Персональные рекомендации Альфа-Курса — запуск одной командой»._

### Слайд 2 — Проблема и пользователь
- 3 персоны: начинающий / владелец микробизнеса / соло-фаундер (разные задачи при одной теме).
- Боль: подбор только по совпадению темы не учитывает стадию, опыт и готовое действие.
- _Заголовок-вывод: «Одной темы мало: пользователям нужен подбор под стадию и задачу»._

### Слайд 3 — Решение
- Отдельный сервис-прототип с рекомендациями (сайт Альфа-Курса не копируем).
- Три опоры: персональный подбор → объяснение каждой рекомендации → следующий шаг.
- _Заголовок-вывод: «Подбираем по профилю и объясняем, почему и что делать дальше»._

### Слайд 4 — Пользовательский сценарий (сквозной пример)
- Короткий необязательный онбординг → профиль → подборка → объяснения → смена подборки под задачу.
- Отдельно: холодный старт (пустой профиль → полезная стартовая подборка).
- Скриншоты UI. _Заголовок-вывод формулируем по реальному примеру._

### Слайд 5 — Архитектура
- Схема: Frontend → Backend API (`POST /api/v1/recommendations`) → ML-движок над каталогом из дампа Альфа-Курса (PostgreSQL).
- Запуск одной командой (docker compose, авто-восстановление дампа), устойчивость: при сбое/отсутствии ML — встроенный скорер того же формата, без 500.
- _Заголовок-вывод: «Стабильный API поверх реального каталога, запуск одной командой»._

### Слайд 6 — Как подбираем материалы
- Признаки: стадия бизнеса, сфера, текущая задача, опыт, предпочитаемый формат, история (просмотры/оценки/прохождения).
- Стратегии: прозрачный metadata-baseline и TF-IDF-гибрид; фильтрация просмотренного/недоступного; холодный старт.
- _Заголовок-вывод: напр. «Гибрид TF-IDF + метаданные обходит подбор по теме»._

### Слайд 7 — Качество (факты, не слова)
- Таблица **«Что пробовали → Что получили → Что выбрали»**.
- Офлайн-метрики на временном holdout: Precision@K / Recall@K / NDCG@K vs бейзлайн «по теме».
- _Заголовок-вывод отражает конкретный результат (с числами)._

### Слайд 8 — Объяснимость и следующий шаг
- Каждая рекомендация: 1–2 причины (`reasons`) + конкретный `next_step`.
- Пример ответа API/карточки. _Заголовок-вывод: «Пользователь понимает, почему материал и что делать»._

### Слайд 9 — Ценность и проверка эффекта
- Бизнес-цель: ↑ конверсия в покупку; продуктовая: ↑ активные дни.
- План A/B (контроль = подбор по теме), главные/guardrail-метрики, офлайн→онлайн. Ссылка: `docs/ab_test_plan.md`.
- _Заголовок-вывод: «Эффект на конверсию проверяем A/B против подбора по теме»._

### Слайд 10 — Ограничения и развитие
- Что уже есть / чего нет: выгрузка `is_paid`/`topic` в каталоге, collaborative filtering, персонализация онбординга.
- Корректная работа с платными материалами (не раскрываем содержание, ведём на страницу покупки по данным ссылкам).
- _Заголовок-вывод: «MVP работает; дальше — CF и тонкая персонализация»._
