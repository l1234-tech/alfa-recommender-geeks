# Сценарий защиты

Основной интерфейс — React на `http://localhost:8080`. Презентация —
[alfa-course.pdf](alfa-course.pdf).

## Перед показом

1. Убедитесь, что SQL-дамп организаторов помещён в `data/alfa_course_hackathon.sql`, если демонстрируете полный каталог. Инструкция: [../data/README.md](../data/README.md).
2. Из корня выполните `docker compose up -d --build --wait`.
3. Откройте React, [Swagger](http://localhost:8000/docs) и [health](http://localhost:8000/health).
4. Выполните smoke-проверку:
   ```powershell
   $env:SMOKE_FRONTEND_URL = "http://127.0.0.1:8080"
   python tools/smoke_http.py
   ```
5. В Swagger проверьте `metadata.catalog_source`: ожидается `database` с восстановленным каталогом или `sample` в демо-режиме. Для основной защиты предпочтителен `database`. В логах backend проверьте `ranking path=engine`.

Если меняли порты, используйте значения из `.env` и скорректируйте адреса smoke-проверки.

## Демонстрация по проверочным сценариям ТЗ

1. **Холодный старт.** В React нажмите «Подобрать без уточнений». Объясните, что профиль необязателен и система возвращает стартовую подборку без длинной анкеты.
2. **Уточнение задачи.** Выберите «Привлечь клиентов» и «Розничная торговля», нажмите «Подобрать материалы». На реальной карточке покажите причину, формат, тему и следующий шаг.
3. **История.** В Swagger отправьте `POST /api/v1/recommendations` с телом:
   ```json
   {"user_profile": {}, "history": [], "limit": 5}
   ```
   Скопируйте `material_id` одной рекомендации и повторите запрос:
   ```json
   {"user_profile": {}, "history": [{"material_id": "ВСТАВЬТЕ_ID", "event_type": "view"}], "limit": 5}
   ```
   Покажите, что этот материал исключён. Важно точно формулировать: текущая история подавляет повторы; она пока не обучает модель предпочтениям пользователя.
4. **Недостаточно данных / нет точного совпадения.** Отправьте профиль с неизвестной отраслью и понятной задачей, например `{"user_profile":{"industry":"ветеринарная клиника","current_goal":"найм персонала"},"history":[],"limit":5}`. Покажите более общую выдачу, если она есть. Не обещайте идеальную релевантность для произвольных формулировок.
5. **Архитектура.** React отправляет запрос через Nginx в FastAPI. Backend загружает метаданные из PostgreSQL и вызывает ML-ранжирование. Без SQL-выгрузки используется явно обозначенный demo-каталог. При ошибке движка доступен резервный скорер.
6. **Оценка и бизнес-эффект.** На 15 синтетических профилях и 1 153 материалах сравнивались подбор по теме, контентный API и гибрид TF-IDF. На трёх профилях с историей гибрид получил nDCG@5 0,55 против 0,48 у бейзлайна. История в текущей реализации исключает просмотренное; цифры не доказывают, что модель учится предпочтениям из истории. 100% рекомендаций API содержат объяснение и следующий шаг. Рост покупок можно установить только экспериментом.

## Выступление на три минуты

- **Проблема (20 с):** предпринимателю нужно быстро найти подходящий материал под конкретную задачу и понять, что делать дальше.
- **Продукт (50 с):** покажите холодный старт, уточнение задачи и карточку реального материала с причиной и следующим шагом.
- **Персонализация (35 с):** покажите профиль и отсутствие повторов по истории. Честно обозначьте, что использование истории как положительного сигнала — следующий этап.
- **Архитектура (25 с):** React → Nginx/FastAPI → ML ranking → PostgreSQL; резервный скорер и demo-режим.
- **Качество и пилот (50 с):** приведите офлайн-метрики с оговоркой о синтетических профилях. Для проверки конверсии предложите A/B 50/50 по пользователю с главным окном 7 дней после сессии.

## Вопросы жюри — короткие ответы

**Почему не просто фильтр по теме?** Ранжирование учитывает несколько признаков профиля, текстовое сходство и формат; гибрид объединяет контентные признаки с TF-IDF. Бейзлайн по теме оставлен для сравнения.

**Как работает холодный старт?** Все поля профиля необязательны. При пустом профиле API формирует стартовую подборку из доступного каталога.

**Что именно делает история?** Исключает уже просмотренные материалы. Она пока не используется как положительный сигнал для обучения предпочтений — это честно обозначенное ограничение MVP.

**Почему TF-IDF?** Он даёт воспроизводимое текстовое сходство по названиям и описаниям без внешнего API и обучения большой модели.

**Доказывают ли метрики рост покупок?** Нет. Precision@5 и nDCG@5 оценивают релевантность офлайн на синтетических профилях. Покупки нужно измерять A/B-тестом.

**Как обрабатываются платные материалы?** Внешний API не получает закрытые тексты. В карточке показывается только допустимая публичная информация; переход на страницу может требовать авторизацию или оплату.

**Что происходит при отсутствии каталога?** Приложение работает на demo-каталоге из 12 материалов и сообщает `catalog_source=sample`. Для проверки полного каталога нужно восстановить SQL и увидеть `catalog_source=database`.

## Ограничения, которые важно не скрывать

- История исключает просмотренное, но ещё не формирует профиль интересов.
- Офлайн-выборка синтетическая и небольшая; результаты нельзя переносить на весь трафик.
- Исходная выгрузка почти не содержит дат покупок и событий по статьям/документам, поэтому конверсию на ней посчитать нельзя.
- Для части типов slug может не иметь публичной страницы; такие ссылки не выдаются. Платные страницы могут требовать авторизацию или оплату.
- A/B-тест требует событийных логов показов, кликов, открытий и покупок.
