# Сравнение контентных и гибридных моделей

## Реализованные подходы

### Metadata baseline
Простое среднее сходства по темам, тегам, отраслям, предпочтительному типу и совпадению токенов цели с названием/описанием.

### TF-IDF
Для каждого материала строится TF-IDF-вектор по открытым полям Title, Description, Topics, Tags и Industries. Профиль пользователя преобразуется в запрос; сходство — cosine similarity.

### Content hybrid
Комбинация:
`score = 0.65 * tfidf_cosine + 0.35 * metadata_score`.
Вес 0.65 — стартовая экспериментальная настройка, а не результат обучения. Если профиль пуст, гибрид возвращает metadata baseline.

### Item-item collaborative filtering
Отдельный алгоритм описан в [collaborative_filtering.md](collaborative_filtering.md). Он использует только высокие оценки и подтверждённые завершения. Сходство строится по совместной положительной истории пользователей.

### Content + CF hybrid
Комбинирует контентную оценку и item-item CF с равными весами, если CF даёт сигнал. При отсутствии CF-сигнала используется контентная оценка — это позволяет обрабатывать cold start.

## Сравнение

`compare_content_models(events, catalog, k=10)` возвращает агрегированные Precision@K, Recall@K и NDCG@K для metadata baseline, TF-IDF hybrid, item-item CF и content+CF hybrid. Каждая модель оценивается на одинаковых temporal splits. Индекс CF внутри каждого split строится только на train events, чтобы не использовать будущие события.

Метрики ещё не запускались на реальной базе данных; нельзя утверждать, что какая-либо модель лучше. Перед выводами нужно выполнить интеграционный прогон, оценить покрытие и проверить устойчивость по нескольким K.

## Ограничения

- TF-IDF — лексическое, а не семантическое сходство.
- Вес TF-IDF 0.65 и веса content/CF 0.5/0.5 — экспериментальные стартовые значения.
- Текущая токенизация не выполняет стемминг/лемматизацию.
- Для строгой оценки также нужен временной снимок каталога на дату теста.
- UUID материалов предполагаются уникальными между типами сущностей.
