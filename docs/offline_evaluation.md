# Профили пользователей и офлайн-оценка

## Положительные события и temporal holdout

Положительные события: оценки `Value >= 4` и подтверждённое завершение курса или урока. Отсутствие события не считается отрицательной меткой. Порог 4 — гипотеза для проверки.

`temporal_holdout` оставляет последние 20% событий каждого пользователя для validation, сохраняя минимум одно событие в train. Тестовая релевантность хранится по ключу `(item_type, item_id)`. Для CF используются события всех пользователей строго раньше начала validation-периода.

## Метрики релевантности

- Precision@K, Recall@K и NDCG@K для общей положительной релевантности.
- Отдельные срезы тех же метрик по типам положительных событий. В каждом срезе учитываются только пользователи с положительным событием данного типа в validation.
- Catalog coverage — доля доступных материалов, появившихся хотя бы в одной рекомендации по всем пользователям.
- Cold-start benchmark — те же ranking-метрики на вручную заданных onboarding-only профилях и ожидаемых релевантных материалах. Это синтетический benchmark, а не оценка реального поведения пользователей.

## Метрики разнообразия

- **Intra-List Diversity (ILD)** — средняя попарная дистанция между материалами внутри одного списка: `1 - JaccardSimilarity` по токенам названия, описания, тем, тегов, отраслей и типа материала. Значение выше означает менее похожие друг на друга рекомендации.
- **Avg unique topics per list** — среднее число уникальных тем в одном списке.
- **Avg unique types per list** — среднее число разных типов материалов в одном списке.

ILD равна нулю для списков короче двух элементов. Для пустого набора списков агрегированные diversity-метрики возвращают ноль.

## Сравнение MMR

`compare_content_models(events, catalog, k=10, diversity_weights=(0.15, 0.25, 0.35))` сравнивает обычные четыре стратегии с MMR-вариантами `content_cf_hybrid` на тех же temporal validation splits. В результате у каждой стратегии есть ranking, coverage и diversity метрики. Это позволяет оценивать компромисс: рост ILD не считается улучшением сам по себе, если при этом существенно падают NDCG@K или Recall@K.

## Ограничения

TF-IDF строится по текущему каталогу, а не историческому снимку. События рейтинга и завершения отражают разные стадии воронки. Jaccard по текстовым метаданным — простой proxy семантического сходства; он зависит от полноты и качества метаданных. Синтетические cold-start cases требуют экспертной проверки и не заменяют онлайн A/B-тест.
