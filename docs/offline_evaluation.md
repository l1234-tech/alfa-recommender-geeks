# Профили пользователей и офлайн-оценка

## Положительные события и temporal holdout
Положительные события: оценки `Value >= 4` и подтверждённое завершение курса или урока. Отсутствие события не считается отрицательной меткой. Порог 4 — гипотеза для проверки.
`temporal_holdout` оставляет последние 20% событий каждого пользователя для теста, сохраняя минимум одно событие в train. Тестовая релевантность хранится по ключу `(item_type, item_id)`. Для CF используются события всех пользователей строго раньше начала тестового периода целевого пользователя.

## Метрики
- Precision@K, Recall@K и NDCG@K для общей положительной релевантности.
- Те же ranking-метрики отдельно по типам положительных событий (например, rating, lesson_progress, course_binding). В срез попадают только пользователи, у которых в test есть положительное событие данного типа.
- Catalog coverage — доля доступных материалов, которые встретились хотя бы в одной рекомендации по всем тестовым пользователям. Это агрегированная метрика набора рекомендаций, а не персонального качества.
- Отчёт содержит агрегаты; user_id не экспортируются.

## Ограничения
TF-IDF пока строится по текущему каталогу, а не историческому снимку. События рейтинга и завершения отражают разные стадии воронки, поэтому раздельные срезы важны. Оценки не являются вероятностями конверсии.
