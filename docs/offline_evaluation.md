# Профили пользователей и офлайн-оценка

## Построение профиля

`build_user_profile` объединяет:
- явно заданные пользователем onboarding-поля;
- темы, теги, отрасли и типы материалов из положительной истории;
- идентификаторы уже встреченных и завершённых материалов для исключения повторов.

Положительные события:
- явная оценка `Value >= 4`;
- подтверждённое завершение курса или урока.

Оценки 1–3 не добавляют предпочтения к метаданным. Отсутствие события не считается отрицательной меткой. Порог 4 — стартовая гипотеза для эксперимента, а не доказанный бизнес-порог.

## Временное разделение

`temporal_holdout` сортирует события каждого пользователя по времени и оставляет последние 20% для теста (минимум одно событие), сохраняя минимум одно событие в train. Пользователи без положительного тестового события пропускаются. Идентификаторы пользователей не возвращаются из функции split.

Это первичная схема оценки. Перед финальным отчётом нужно проверить пропуски дат и повторные события одного материала, а также сравнить результат с несколькими временными срезами.

## Метрики

- Precision@K — доля рекомендаций в top-K, попавших в отложенные положительные события; знаменатель K.
- Recall@K — доля отложенных положительных материалов, найденных в top-K.
- NDCG@K — качество порядка релевантных материалов с дисконтированием по позиции.

Метрики усредняются по пользователям. В отчёт возвращаются только агрегаты и количество оценённых пользователей; сырые user_id не экспортируются.

## Важные ограничения

- События разных типов пока бинаризуются для определения позитивного тестового множества; нельзя трактовать это как калиброванную вероятность интереса.
- Рейтинги и завершения могут отражать разные стадии воронки. В следующем эксперименте следует считать метрики отдельно по типам событий.
- В текущей модели нет negative sampling и нет collaborative filtering.
- Рекомендательная выдача исключает ранее встреченные item_id; это соответствует задаче поиска нового контента, но может влиять на Recall при повторных событиях.
- При отсутствии onboarding и истории профиль пустой: система возвращает доступный каталог с детерминированной сортировкой, что является техническим fallback, а не персонализацией.
