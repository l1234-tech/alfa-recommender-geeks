# Профили пользователей и офлайн-оценка

## Положительные события и temporal holdout

Положительные события: оценки `Value >= 4` и подтверждённое завершение курса или урока. Отсутствие события не считается отрицательной меткой. Порог 4 — гипотеза для проверки.

`temporal_holdout` оставляет последние 20% событий каждого пользователя для validation, сохраняя минимум одно событие в train. Тестовая релевантность хранится по ключу `(item_type, item_id)`. Для CF используются события всех пользователей строго раньше начала validation-периода.

## Метрики

Используются Precision@K, Recall@K, NDCG@K, catalog coverage, Intra-List Diversity, среднее число уникальных тем и типов материалов. События разных типов также анализируются отдельными срезами.

## Подбор гибридных весов

`tune_hybrid_weights(events, catalog, k=10)` выполняет перебор на одинаковых temporal validation splits:

- `tfidf_weight` и дополнительный вес метаданных `1 - tfidf_weight`;
- `content_weight` и вес CF `1 - content_weight` для content+CF гибрида.

Для каждой конфигурации возвращаются только агрегированные метрики. CF-индекс для каждого пользователя строится один раз на его допустимой предшествующей истории, затем переиспользуется при переборе весов. Результаты сортируются по NDCG@K, затем Recall@K, Precision@K и coverage.

Это подбор гиперпараметров на validation, поэтому лучший вариант нельзя считать независимой оценкой качества. После выбора кандидата необходим отдельный, не использованный при подборе test-период. Кроме того, TF-IDF пока строится по текущему каталогу, а не историческому снимку.

## Разнообразие и MMR

ILD — средняя попарная дистанция между материалами внутри списка: `1 - JaccardSimilarity` по текстовым и структурным метаданным. MMR позволяет управлять компромиссом между релевантностью и разнообразием. Рост ILD сам по себе не считается улучшением, если существенно падают NDCG@K или Recall@K.

## Ограничения

События рейтинга и завершения отражают разные стадии воронки. Jaccard по текстовым метаданным — proxy семантического сходства. Синтетические cold-start cases требуют экспертной проверки. Фактические метрики на реальной БД не заявляются до запуска на разрешённой выгрузке.
