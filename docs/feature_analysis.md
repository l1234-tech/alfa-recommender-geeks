# Анализ признаков для персонализации

## Признаки материалов

- Текст: Title и Description из открытых метаданных.
- Темы, теги и отрасли: через ContentSettingsTopics, ContentSettingsTags, ContentSettingsIndustries для Articles, Courses, Documents, Webinars и Podcasts.
- Тип материала: article, course, document, webinar, podcast, lesson, calculator.
- Доступность: Published, IsDeleted, IsClosed и связи с доступным курсом. Для Lessons применяется консервативное правило: trial-урок или урок курса с Cost IS NULL.
- В исходном анализе также найдены потенциальные поля: Duration, LessonQuantity, Cost, HasTrial, IsCertified, StartsAt, SubjectId и IsLesson. Они пока не включены в модель: требуется проверить полноту, семантику, утечку целевой переменной и сопоставимость между типами.

## Признаки взаимодействий

- Оценка: UserRatings.Value и Created. EntityId сопоставлен с Lessons и Calculators.
- Персональные оценки: только 2 325 строк имеют UserId; анонимные оценки не входят в user-item события.
- Прохождение курса: IsCompleted, Completed, LessonsCompleted, StudyingStartDate.
- Прохождение урока: Completed — timestamp; завершение равно Completed IS NOT NULL.
- Теги оценки: UserRatingTagsBindings.

## Внешний профиль

В дампе нет подтверждённой таблицы с бизнес-стадией, текущей задачей и уровнем опыта предпринимателя. Эти признаки должны приходить из onboarding/API.

## Изменения контентных признаков

- TF-IDF использует только открытые Title, Description, Topics, Tags, Industries и тип материала.
- Title получает умеренное усиление частоты термов (2x), потому что это короткое редакционное описание материала.
- Структурные onboarding-поля (темы, теги, отрасли) получают дополнительное представление в запросе пользователя.
- Metadata baseline усредняет только сопоставимые поля: отсутствие тега или отрасли у материала не считается отрицательным совпадением.
- Дубли одного typed key отклоняются при построении TF-IDF, чтобы не перезаписывать вектор молча.

Эти изменения — прозрачные эвристики, а не обученные веса. Их влияние должно проверяться на validation и экспертных кейсах.

## Правила

- Не считать отсутствие оценки негативной меткой.
- Не трактовать CourseUserBindings как просмотр курса.
- Не смешивать рейтинги и прогресс в один сигнал без эксперимента.
- Исключать недоступные материалы.
- Не использовать UserId, IP и закрытый Content как признаки.
- Текущая модель не использует длительность/стоимость/сертификацию до проверки семантики и риска утечки.
