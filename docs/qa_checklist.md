# QA-чеклист и сценарии для демо

Чеклист отражает **текущее поведение реализации**, а не желаемые функции будущих версий. Отмечайте пункты только после фактического прогона. Автоматические проверки: `pytest`, frontend `npm test`, `tools/smoke_http.py`.

## 0. Допуск и запуск

- [ ] Чистый клон: `Copy-Item .env.example .env` (PowerShell), затем `docker compose up -d --build --wait`.
- [ ] `GET /health` возвращает `{"status":"ok"}`.
- [ ] React открывается на `http://localhost:8080`, Swagger — на `http://localhost:8000/docs`.
- [ ] В репозитории нет локального `.env`, рабочих ключей и исходной выгрузки.
- [ ] Есть `.dockerignore`, Dockerfile обоих приложений и зафиксированные версии Python-зависимостей.
- [ ] При запуске без SQL API сообщает `metadata.catalog_source=sample`.
- [ ] При запуске с SQL API сообщает `metadata.catalog_source=database`, в логах есть `Catalog loaded from database` и `ranking path=engine`.

## 1. Сценарии трека 1

| # | Действие | Фактическое ожидаемое поведение | Статус |
|---|---|---|---|
| 1 | Отправить пустой профиль | API возвращает стартовую подборку из доступного каталога; `cold_start=true`, если история также пуста | [ ] |
| 2 | Указать задачу, отрасль, стадию и опыт | Признаки профиля участвуют в content-baseline / TF-IDF-гибридном ранжировании | [ ] |
| 3 | Передать ID просмотренного материала в `history` | Материал исключается из следующей выдачи; история **не** обучает предпочтениям и не меняет профиль интересов | [ ] |
| 4 | Передать неизвестную отрасль или формулировку без совпадения | API продолжает возвращать доступные материалы; при нулевых оценках UI явно сообщает об отсутствии точного совпадения и предлагает сбросить профиль для общей подборки | [ ] |
| 5 | Передать все ID доступных материалов в историю | API может вернуть пустой список; UI предлагает сбросить профиль и запросить общую стартовую подборку. История в UI сейчас не накапливается | [ ] |
| 6 | Выбрать предпочитаемый формат | Формат влияет на ранжирование как мягкий сигнал, но не является жёстким фильтром | [ ] |

## 2. Карточки рекомендаций

- [ ] Каждая карточка содержит название и тип материала.
- [ ] Если в каталоге есть описание, оно показывается; для платного материала описание из API скрывается.
- [ ] Каждая рекомендация содержит объяснение и следующий шаг.
- [ ] Если публичная ссылка не может быть безопасно построена, UI не предлагает переход и показывает, что материал пока недоступен.
- [ ] Для платных материалов не раскрывается подробное содержание; страница может требовать авторизацию или оплату.

## 3. Неполные данные и устойчивость

- [ ] Пустые необязательные поля допустимы.
- [ ] Некорректные значения профиля отклоняются UI-валидацией; API проверяет структуру запроса.
- [ ] Несуществующий ID в истории не вызывает ошибку.
- [ ] Повторный одинаковый запрос даёт стабильную сортировку при неизменном каталоге и конфигурации.
- [ ] Ошибка API отображается с возможностью повторить запрос.
- [ ] В frontend работают состояния загрузки, ошибки и пустой выдачи.

## 4. Интерфейс

- [ ] Все поля уточнения профиля необязательны; пустой профиль можно отправить.
- [ ] Нет навязчивых поп-апов.
- [ ] Основная форма и карточки читаемы на мобильной ширине.

## 5. Команды проверки

Из корня репозитория после установки backend-зависимостей:

```powershell
python -m pytest -q
$env:SMOKE_FRONTEND_URL = "http://127.0.0.1:8080"
$env:SMOKE_CATALOG_SOURCE = "database" # только после импорта SQL
python tools/smoke_http.py
```

Из `frontend/`:

```powershell
npm ci
npm run build
npm run typecheck
npm run lint
npm test
```

Проверка логов Docker после запросов к API:

```powershell
docker compose logs --since=5m backend | Select-String "Catalog loaded from database|ranking path=engine|ranking path=builtin"
```

## 6. Известные ограничения (не считать пройденными функциями)

- История просмотров подавляет повторы, но не используется как положительный сигнал интересов.
- Collaborative filtering реализован в ML-пакете, но не подключён к основному API-пути.
- Для профиля без точных совпадений выдаётся общий доступный каталог; UI предлагает сбросить профиль. Автоматического уточняющего диалога и персонального учебного маршрута пока нет.
- UI не сохраняет и не накапливает историю просмотров между запросами.
- Офлайн-метрики на синтетических профилях не доказывают рост покупок; для этого нужен A/B-тест с событийным логированием.
