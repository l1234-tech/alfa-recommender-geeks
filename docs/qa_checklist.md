# QA-чеклист и сценарии для демо

Прогоняется руками перед сдачей и перед защитой. Автоматическая часть:
`pytest` и `python -m analytics.evaluate --algo api=http://localhost:8000/api/v1/recommendations`.

## 0. Запуск (критерий «Допуск» — без него 0 баллов)
- [ ] Чистый клон → `cp .env.example .env` → `docker compose up --build` поднимается без ручных правок
- [ ] `GET /health` → `{"status": "ok"}`
- [ ] Фронтенд открывается, адрес и порт совпадают с README
- [ ] В репозитории нет `.env`, ключей и исходной выгрузки (`git ls-files | grep -iE "env$|csv|xlsx|parquet"`)
- [ ] Есть `.dockerignore`, версии в requirements зафиксированы

## 1. Сценарии из ТЗ (приложение 2)

| # | Шаги | Ожидаем | Профиль |

| 5 | Задача свободным текстом с опечатками («где брать покупателей», «налоги ип скока платить») | Правильная тема распознана | p09, p13 |

## 2. Объяснения и следующий шаг
- [ ] У каждой карточки есть «почему рекомендуем», и тексты разные, а не один шаблон
- [ ] В объяснении упомянуто что-то из профиля (стадия, задача, опыт или история)
- [ ] Следующий шаг конкретный: «открыть», «скачать шаблон», «перейти к курсу»

## 3. Платные материалы (ограничение 06 из ТЗ)
- [ ] Для платных показывается только краткая польза и ссылка на страницу материала
- [ ] Подробное содержание платного курса не раскрывается
- [ ] Платные не забивают топ: первым идёт бесплатный материал

## 4. Неполные и плохие данные
- [ ] Пустые поля, `null`, неизвестные значения, очень длинный текст → нет ошибки 500
- [ ] Несуществующий material_id в истории → не падает
- [ ] Одинаковый запрос → одинаковая выдача (чтобы демо было стабильным)

## 5. Интерфейс
- [ ] Онбординг короткий и необязательный, есть кнопка «пропустить»
- [ ] Нет навязчивых поп-апов
- [ ] Работает на ширине мобильного экрана
