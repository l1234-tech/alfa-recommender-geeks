### Покрытие UserRatings пользовательскими ID

Из 8 343 оценок:
- 2 308 оценок Lesson имеют UserId;
- 2 223 оценки Lesson не имеют UserId;
- 17 оценок Calculator имеют UserId;
- 3 795 оценок Calculator не имеют UserId.

Итого только **2 325 из 8 343** оценок можно связать с пользователем для персональной истории. Анонимные оценки нельзя включать в user-item матрицу; при отдельной задаче их можно анализировать только как агрегатный item-level сигнал.

### Сопоставление EntityTypeId

`ContentSettings.EntityTypeId` и `UserRatings.EntityTypeId` — разные пространства типов. Для ContentSettings сопоставление с Courses, Podcasts, Articles, Documents и Webinars подтверждено точным пересечением EntityId с PK. Для UserRatings фактические EntityId сопоставляются с Lessons и Calculators. Подробности — в [entity_mapping.md](entity_mapping.md).

## Ограничения

1. Отсутствие оценки/события не означает негативное предпочтение.
2. `CourseUserBindings` — связь пользователя с курсом и состояние обучения/доступа, не просмотры всех материалов.
3. `CourseUserLessonBindings.Completed` — timestamp; завершение определяется как `Completed IS NOT NULL`.
4. `RecommendedItems` нельзя автоматически считать позитивными взаимодействиями без выяснения семантики.
5. В дампе нет подтверждённой таблицы бизнес-профилей пользователей. Бизнес-стадия, отрасль и текущая задача должны приходить из onboarding/API.
6. UserId и IP не включать в признаки, публичные логи или документацию.
7. Для платных материалов используем открытые метаданные, не закрытое содержимое.
8. Веса baseline пока не обучены; требуется офлайн-оценка на временном holdout.
